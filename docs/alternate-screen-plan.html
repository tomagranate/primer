Alternate screen setup plan

Move Primer's live setup from cursor-owned scrollback into an app-like alternate screen, while always returning the terminal to normal mode and printing a durable summary.

Mode change

Interactive TUI during live setup; normal scrollback summary after exit.

Safety rule

Cleanup must restore cursor, leave alternate screen, and preserve temp data long enough for reporting.

Default path

TTY runs use alternate screen by default; non-TTY runs stream plain logs. CLI flags can force either mode.

1. Terminal lifecycle 2. Interactive setup UI 3. Summary and exits 4. Tests and rollout

1. Terminal lifecycle

Introduce a single terminal session API so alternate screen entry, repainting, signal cleanup, and final reporting are controlled from one place.

Create explicit UI modes

Foundation
  • Add a mode variable such as PRIMER_UI_MODE=alternate|log.
  • Default to alternate when stdout is a TTY.
  • Default to log when stdout is not a TTY, with simple progress and module log lines printed as work happens.
  • Add CLI flags such as --tui and --log to force either mode.

Add alternate screen enter and leave helpers

Terminal
  • Use \e[?1049h to enter alternate screen and \e[?1049l to leave it.
  • Hide the cursor on enter and show it on every exit path with \e[?25l and \e[?25h.
  • Use the existing UI_REPAINT_MODE=full behavior for full-screen redraws instead of cursor-up frame ownership.

Centralize cleanup

High risk
  • Replace scattered live-render cleanup with one engine::_finish_terminal_ui style function.
  • Make cleanup idempotent so traps and normal completion can both call it safely.
  • Do not remove PRIMER_TMPDIR until final summary and error boxes have been printed.

2. Interactive setup UI

Convert the current live frame into a richer viewport layout while preserving the existing DAG executor and module status file contract.

Split render output into regions

UI
  • Render a persistent header with command name, dry-run state, elapsed time, and total progress.
  • Render the module list as the primary center pane using the existing ui::module_line formatting at first.
  • Render active sub-items and recent module detail in a lower pane, clipped to terminal height.

Keep input minimal in v1

Interaction
  • Do not require raw keyboard mode for the first pass; keep Ctrl-C handled by shell traps.
  • Reserve future keys for expanding modules, switching panes, or viewing logs after the alternate screen lifecycle is stable.
  • Allow setup work to continue exactly as it does now; this change should be a presentation layer first.

Handle terminal size deliberately

Viewport
  • Read LINES, COLUMNS, and tput values per render, matching the current layout refresh pattern.
  • Clip module and item lists to fit within the alternate screen instead of relying on scrollback.
  • Show compact overflow lines like ... 12 more when lists exceed the viewport.

3. Summary and exits

The key product behavior: alternate screen is temporary, but the final result is permanent in normal terminal history.

Print a normal completion report

Required
  • On success, leave alternate screen, restore cursor, then call the existing final expanded render in normal scrollback.
  • Keep failed module error boxes in normal scrollback so users can copy details after the process exits.
  • Include elapsed time and the same done, failed, skipped, and waiting counts already produced by engine::_summary.

Print an interrupted report on Ctrl-C

Signals
  • Trap INT and TERM, mark still-running modules as interrupted or skipped, and stop polling new work.
  • Leave alternate screen before printing the interrupted report.
  • Return a non-zero exit code after the report is printed.

Best-effort report on unexpected error

Error path
  • Trap EXIT and detect non-zero exits that have not already reported.
  • Restore the terminal first, then print whatever module state and logs are available.
  • Accept that hard kills such as SIGKILL cannot run cleanup or print a summary.

4. Tests and rollout

Update terminal stress coverage around the new default TTY mode and the simple non-TTY log mode.

Replace old repaint assumptions

Regression
  • Update the existing no-live-scroll test so TTY runs expect alternate screen instead of rejecting it.
  • Remove cursor-up repaint expectations from the default path.
  • Keep regression coverage that the final expanded report appears in normal scrollback after the TUI exits.

Add alternate mode terminal probes

Acceptance
  • Assert the raw stream enters and leaves alternate screen exactly once during a normal TTY run.
  • Assert cursor show is emitted after normal completion, Ctrl-C, and synthetic module failure.
  • Assert the final normal-screen report appears after \e[?1049l.

Cover forced log mode

Non-TTY
  • Assert redirected output and --log never emit alternate-screen or cursor-control escapes.
  • Assert module progress and module logs are printed incrementally in log mode.
  • Assert --tui can force alternate mode only when a usable TTY is available; otherwise fail clearly or fall back to log mode.

Target lifecycle

The implementation should make the terminal state machine obvious enough that every path can be audited.
